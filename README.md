# 東方数紙業

東方Project 二次創作のカードドラフトゲーム（スシGO 風メカニズム × 幻想郷のステージテーマ）。
Web ゲーム（HTML/JS + `ws`）として動作する。

> 東方Project二次創作ガイドラインに従い、非商用の個人ゲームとして制作。

## 公開（Render）

`render.yaml` を置いてあるので、Render の「New → Blueprint」からこのリポジトリを選ぶだけで公開できます。

- サービス名: `tohogo`（変更可）／プラン: Free／ヘルスチェック: `/healthz`
- WebSocket は同じポートで動くので、そのまま対戦も可能
- **無料プランは 15 分アクセスが無いとスリープ**し、その間のルーム（メモリ保持）は消えます

### スリープ対策

- **画面を開いている間だけ**、クライアントが 5 分ごとに `/keepalive` を叩きます（タブが非表示の間は停止）
- 誰もアクセスしていない時はスリープさせます。無料プランの月間時間を無駄に消費しないため、常時 ping は行いません

## 遊び方

```bash
npm start
# → http://localhost:3010 を開く
```

- 最初の画面で「ひとりで遊ぶ（AI3人）」か「みんなで遊ぶ（ルーム）」を選ぶ
- ひとりモードでもステージを選べる（おまかせ / 紅霧 / 春雪 / 永夜 / 風神録）
- 3 ラウンド・各ラウンドで手札から 1 枚選んで隣にパス（スシGO 流ドラフト）
- 同点は**継続カードの合計枚数が多い方**が上位。それも同じなら同率1位
- ゲーム開始時に**ステージが 1 つ抽選**され、デッキの顔つきが全く変わる

### 対戦（2〜5人）

- 「ルームを作る」→ 表示された 4 文字コードを相手に伝える
- 相手は「コード」を入れて「参加する」
- **ルームマスター**が「ステージ」と「取得時間（30秒 / 60秒 / 無制限）」を設定できる（開始後は変更不可）
- ホストが「ゲーム開始」を押すと開始
- 手札は各自の画面にだけ表示（山札・他人の手札・未公開のピックはサーバーが隠す）
- 取得時間を過ぎると AI が代行する（残り時間は画面右上に表示）。ラウンド結果バナーは 10 秒で自動的に閉じる
- 切断しても、同じ名前・同じルームで入り直すと元の席に戻る
- 切断した席は**2 分間の猶予**のあいだ AI に切り替えず、再接続を待つ。2 分経過で AI が代行する（画面上部に残り時間が出ます）

```bash
npm test
# ルールテスト（109 テスト）を実行
npm run test:room
# ルーム管理の単体テスト（ホスト移譲・claim・view 契約・残り時間）

# 対戦サーバーのスモークテスト（create/join/start/ピック/秘匿/再接続）
npm run test:ws-game

npm run test:serve

npm run test:consistency
# カード枚数の保存則（全異変 × 2/3/4 人 × seed。-- で --full を渡すと全 sweep）
npm run test:all
# 上記をまとめて実行（CI 相当）
```

## ステージセットシステム

ゲーム開始時に 4 つのステージから 1 つが抽選される。各ステージは独立したカードセット
（10 種・メイン 54 枚＋継続カードプール 15 枚）を持ち、駆け引きの「形」が異なる。

| ステージ | 物語 | 駆け引きの形 |
|---|---|---|
| 紅魔館（紅魔郷） | 紅い館の連携 | キャラ間連携（咲夜×美鈴・大妖精×チルノ） |
| 白玉楼（妖々夢） | 桜をめぐる攻防 | 軸（春）への 4 方向攻防 |
| 永遠亭（永夜抄） | 月をめぐる管理 | 数量の管理とジレンマ（偶奇・豆腐・霊夢/魔理沙） |
| 守矢神社（風神録） | 信仰と厄払い | 信仰の到達レースと厄の押し付け |

- 継続カード枠（チルノ / リリーホワイト / 妹紅 / 犬走椛）は継続カードプールから
  ラウンドごとに 5/3/2 枚山札に混入し、ゲーム末（またはラウンド末）に判定される
- ラウンド終了時に取得カードは継続カード以外すべて山札に戻る（スシGOパーティー準拠）
- 永遠亭はゲーム開始時に霊夢か魔理沙のどちらか 1 種だけがデッキに加わる

詳細は `DESIGN.md` を参照。

## カードイラスト

全31種のカードに生成イラスト（512×768 WebP）を用意している。

- 生成: ComfyUI + **MOSS-Image 4step**（Danbooru タグ・露出控えめ・カメラワーク指定）
- プロンプト: `tools/card-art/build-candidates.py` がキャラごと3案ぶんを `tools/card-art/runs-cand.json` に出力
- 採用理由と正史タグの根拠: `tools/card-art/characters.md`（キャラ追従チェック表）
- 変換: `tools/process-card-art.py` が 2:3 にセンタークロップして `assets/cards/<key>.webp` を出力
- 画像が無いカードは色＋字のフォールバックで表示される

再生成する場合（Strata は停止しておく）:

```bash
# 1. ComfyUI を単独起動（バックグラウンドジョブで実行）
pwsh -File tools/start-comfyui.ps1

# 2. キャラごと3案を生成（93枚）
python tools/card-art/build-candidates.py 3
pwsh -File tools/comfy-standalone.ps1 -SkipStart -Manifest tools/card-art/runs-cand.json

# 3. 3案を並べた判定シートを作る
python tools/card-art-candidates-sheet.py .tmp/card-art-cand/raw .tmp/card-art-cand/sheets 5 210

# 4. 採用案を WebP 化（採用表は assemble-final.py の PICK）
python tools/card-art/assemble-final.py
```

旧セット（Qwen-Image 2.1 turbo / `tools/card-art/runs.json`）も残してある。

### バランス確認

```
npm test                        # ルールテスト
npm run sim                     # 全ステージ × 300 ゲーム（AI 4 人）
npm run sim -- --games 1000     # 試行回数を増やす
npm run sim -- --incident spring --top 20
npm run sim -- --csv > sim.csv  # スプレッドシート用
npm run sim -- --out .tmp/sim-report.txt  # UTF-8 ファイルにも書き出す（Windows の文字化け対策）
npm run sim -- --ablate y_kaguya          # 点数を 1 下げたときの影響（感度分析）
```

指標は 2 つあり、用途が違う。

**卓平均差（相対指標）** — そのカードを取った人が同じラウンドで他プレイヤーより何点上だったかの平均。
+ が大きい = 持っていると勝ちやすい、− が大きい = 持っていても勝てない。
ただし全員が同じ頻度で強いカードを引くため **カードの絶対的な強さは相殺される**。
実際、点数を動かしても単調に動かない（4 点でも 2 点でも同じ値になったりする）。
条件付きカード・継続カードは構造的に下振れするので、これ単独で弱いと断定しないこと。

**感度分析 `--ablate`（絶対指標）** — 指定カードの点数を `--step` 点（既定 −1）動かして再実行し、
卓全体の平均合計点が何点動くかを見る。点経済への寄与を素直に測れるので、
ナーフ・バフの効き具合はこちらで確認する。`--seed` で乱数を固定できる。

**得点源の分解** — `npm run attrib` で、カード 1 種類の得点ロジックを 0 にして再実行し、
セット平均が何点下がるか（＝そのカード全枚数の寄与）を一覧にする。
`1枚あたり` 列は点が枚数に比例する instant だけ算出する。マキ・手巻き・共闘・収集などは
枚数や順位で段階的に変わるため、割り算した値に意味がない。
「1 枚が強い」のか「枚数が多いから合計が大きい」のかを切り分けるのに使う。

```
npm run attrib
npm run attrib -- --incident eternal --games 1500 --out .tmp/attrib.txt
```

**所持枚数分析 `--by-card`** — 指定カードを「ラウンド内に何枚持ったか」ごとに、ラウンド点の卓平均との差と
勝率を出す。取るほど勝てるカード（dominant）と、取るほど損になるカード（sucker）を切り分けられる。

```
npm run sim -- --games 1500 --by-card y_tewi
npm run sim -- --games 1500 --by-card y_riggle
```

### AI の検証

```
npm run ai-check
```

AI の評価関数が「標準的」と言えるかを 3 つの観点で確認する（5600 ゲーム＝1400 × 4 異変、標準誤差 約0.7%）。

1. **同型対戦** — 同じ AI 4 人で 25% 前後（偏りがない）
2. **摂動耐性** — 評価を ±10% ずらした相手に負けない（簡単に搾れない）
3. **異種混合** — 癖のある相手 3 人（即時好き・セット好き・順位＋継続カード好き）を相手に 18% 以上

カード評価を変えたら、ここが合格するか確認する。
